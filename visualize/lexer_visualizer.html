A lexer is the first stage of a compiler: it splits code into labelled pieces called tokens. Pick a program or scan your own, then watch it happen one step at a time.

  1. 1RegexEach token type is a pattern, like [0-9]+.
  2. 2PostfixThe pattern is rewritten so a program can build it step by step.
  3. 3NFAThe postfix becomes a machine of states that reads characters.
  4. 4Maximal munchAt each position every rule tries; the longest match wins.
  5. 5TokensWinners are emitted; whitespace and comments are dropped.
Steps 4–5 · scanning

Scanning

What is this?

Each cell is one character of the input. The orange marker is the read head: where the lexer is right now. A cell's colour is the token type it ended up in. Grey cells are whitespace or comments, which are read but thrown away. Red cells are characters no rule could match.

Press Next or Play to move the read head. Click any cell or token to jump straight to it; the arrow keys step too.

Why this token?

What is this?

At every position, every rule runs its NFA on the text ahead and reports how many characters it can match. Each bar shows that length.

This is maximal munch: the longest match wins. If two rules match the same length, the one with the lower priority number wins, which is why if becomes a KEYWORD rather than an IDENT, while iffy is an IDENT because it is longer.

If no rule matches at all, the lexer reports an error, skips that one character and carries on.

Token stream

What is this?

The lexer's output, in order, with line:column. This list is what the next compiler stage, the parser, receives. Whitespace and comments are not in it; errors are shown in red.

    Optional Try a single pattern matching a whole string vs. just its start

    A string counts as a match only if the pattern covers all of it. Often a pattern matches just the start, shown as "prefix 1/5". That is exactly what the scanner relies on: at each position it only needs the longest start that matches.
